# Adapter

This package provides the online input adapter used by both GLIM mapping and
GICP localization.

The adapter is not tied to Putnam Park, a specific map, or a specific rosbag.
It normalizes live or replayed vehicle data into the topic contract expected by
the mapping and localization stack:

- `/gps_p1/imu`
- `/gps_p1/filtered_odom`
- `/gps_p1/filtered_odom_rtk_fixed`
- `/gps_p1/filtered_odom_map` when `T_world_utm_path` is provided
- `/luminar_front/points`, `/luminar_left/points`, `/luminar_right/points`
  when LiDAR bridging is explicitly enabled

## Why This Exists

GLIM and GICP should not need to know whether the upstream data came from a
live Point One Atlas driver, a rosbag topic, or a PCAP replay source. They
should consume the same normalized topics in every run.

The adapter keeps that boundary explicit:

- Atlas FusionEngine pose messages are converted into `/gps_p1/*` odometry.
- Atlas IMU messages are retimed from P1 measurement time into the replay ROS
  clock domain when needed.
- A Point One IMU PCAP can be replayed as an online ROS source when the bag IMU
  stream is not the desired source of truth.
- Luminar clouds can be bridged from `/dlio_raw/luminar_*` to `/luminar_*`, but
  that bridge is off by default because many bags already contain the normalized
  `/luminar_*` topics.

This keeps GLIM and GICP source-agnostic while preserving the P1 measurement
time needed for LiDAR/IMU alignment.

## Launch

Use the single public launch file:

```bash
ros2 launch adapter adapter.launch.py \
  p1_imu_pcap_path:=/path/to/ins.pcap
```

The default mode consumes these upstream topics:

```text
/atlas/pose_filtered
/atlas/imu_calibrated_pcap
/luminar_front/points
/luminar_left/points
/luminar_right/points
```

and publishes normalized `/gps_p1/*` topics for GLIM and GICP. Point One IMU
PCAP replay is enabled by default; pass `p1_imu_pcap_path` for normal runs.

## With Point One IMU PCAP

Point One IMU PCAP is the default IMU source. Pass `p1_imu_pcap_path`; the
launch file starts the PCAP replay node and automatically points the adapter
at its output topic.

```bash
ros2 launch adapter adapter.launch.py \
  p1_imu_pcap_path:=/path/to/ins.pcap
```

By default the PCAP source publishes to `/atlas/imu_calibrated_pcap`, not
`/atlas/imu_calibrated`. This avoids colliding with an IMU stream that may
already be present in the rosbag. The adapter then consumes
`/atlas/imu_calibrated_pcap`.

The PCAP replay is still online: it reads the PCAP sequentially and paces
messages from `/clock` by default.

To explicitly use an upstream ROS IMU topic instead of PCAP, disable the PCAP
source:

```bash
ros2 launch adapter adapter.launch.py \
  use_p1_imu_pcap:=false \
  imu_input_topic:=/atlas/imu_calibrated
```

## With Raw LiDAR Namespace

If the input uses `/dlio_raw/luminar_*` instead of `/luminar_*`, enable the
LiDAR bridge:

```bash
ros2 launch adapter adapter.launch.py \
  p1_imu_pcap_path:=/path/to/ins.pcap \
  enable_lidar_bridge:=true
```

Leave `enable_lidar_bridge` false when the source already publishes
`/luminar_*`. In that case GLIM and GICP should consume the bag/live LiDAR
topics directly, while the adapter only normalizes the Atlas/P1 data.

## Map-Frame Odometry For GICP

GICP usually needs `/gps_p1/filtered_odom_map`, which requires the map export
transform generated by GLIM:

```bash
ros2 launch adapter adapter.launch.py \
  p1_imu_pcap_path:=/path/to/ins.pcap \
  T_world_utm_path:=/path/to/T_world_utm.txt
```

Without `T_world_utm_path`, the adapter still publishes `/gps_p1/filtered_odom`
and `/gps_p1/filtered_odom_rtk_fixed`, but it does not publish
`/gps_p1/filtered_odom_map`.

## Common GLIM Replay

```bash
ros2 launch adapter adapter.launch.py \
  p1_imu_pcap_path:=/path/to/ins.pcap

ros2 bag play /path/to/bag --clock --rate 1.0
```

GLIM can then consume `/gps_p1/imu`,
`/gps_p1/filtered_odom_rtk_fixed`, and `/luminar_front/points` through its
normal configuration.

## Common GICP Replay

```bash
ros2 launch adapter adapter.launch.py \
  p1_imu_pcap_path:=/path/to/ins.pcap \
  T_world_utm_path:=/path/to/T_world_utm.txt

ros2 bag play /path/to/bag --clock --rate 1.0
```

GICP can then consume `/gps_p1/imu`, `/gps_p1/filtered_odom_map`, and the
`/luminar_*` clouds through its normal configuration.
